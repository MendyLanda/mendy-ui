## How it works

`AppliedFilter` combines a chip, an edit trigger, an editor, and an optional remove button. Pass the current summary as children. Pass an editor as `editor`, and handle changes in your application state.

- Editing and removal are separate buttons with separate accessible labels.
- New chips slide up and fade in. Reduced-motion preferences turn this off.
- Single selection applies immediately and closes the editor.
- Multiple selection applies immediately and keeps the editor open.
- Text stays in a local draft until Enter. Close without applying to discard it.
- A required filter can omit `onRemove` and remain editable.

The table above combines different filter fields with AND. Multiple assignees match with OR. Those choices belong to this demo's matching function; the components do not prescribe them.

## Built-in editors

Use `FilterSelectEditor` for one option, `FilterMultiSelectEditor` for several options, and `FilterTextEditor` for text. Both selection editors support optional search. [See the examples](/docs/examples).

## Custom editors

Use `FilterChip`, `FilterEditor`, `FilterEditorTrigger`, `FilterEditorContent`, and `FilterRemove` to build a custom layout. Use `FilterMenuItem` for an options submenu and `FilterCheckboxItem` to keep it open after selection. For searchable or text editors in a submenu, pass `contentProps={{ role: "dialog", "aria-label": "Filter options", "aria-orientation": undefined }}`. Built-in selection editors supply the labeled menu inside that dialog.

The core component does not depend on a table library, a router, or an API client. Connect `onValueChange`, `onValuesChange`, and `onApply` to your state or URL persistence layer.

## Keyboard and focus

- Tab to the edit or remove button.
- Enter or Space opens the editor. Arrow keys navigate menu options.
- In searchable editors, type in the search field; Arrow Down moves to the first available option.
- Escape dismisses the editor and restores focus to its trigger.
- Text inputs keep typing and cursor keys inside the field instead of triggering menu typeahead.

If removing a chip also removes the focused element, your application should move focus to a sensible neighbor or the add-filter button. Custom editors must supply their own labels and keyboard behavior.
