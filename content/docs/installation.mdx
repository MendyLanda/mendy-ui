## Install

Use React 19. The package includes its controls and compiled CSS, so you do not need local shadcn files or a Tailwind build to use it.

<InstallCommand />

Import the stylesheet once in your application's root layout or entry point:

```tsx
import "@mendylanda/ui/styles.css";
```

The stylesheet is scoped to Mendy UI elements, including dropdowns. It uses your shadcn color variables and radius, with neutral defaults when those variables are absent. It inherits your font. It does not reset the rest of your application. No Tailwind `@source` entry for the package is needed.

## Define your filters

```tsx
"use client";

import { defineFilters, filter, FilterBar, useFilters } from "@mendylanda/ui/filters";

const definitions = defineFilters({
  status: filter.select({
    label: "Status",
    options: [
      { value: "open", label: "Open" },
      { value: "closed", label: "Closed" },
    ],
    suggestion: { value: "open" },
  }),
  owner: filter.multiSelect({
    label: "Owner",
    options: [{ value: "mendy", label: "Mendy" }],
    searchable: true,
  }),
});

export function IssueFilters() {
  const filters = useFilters(definitions);
  // filters.values.status is "open" | "closed" | null.
  // Use filters.values and filters.search in your data query.
  return <FilterBar filters={filters} />;
}
```

Definitions and data queries stay in your app. Focus, editing, suggestions, paste recognition, menus, and chip summaries stay in the package.

## URL persistence

Install nuqs when you want URL state:

```sh
npm install nuqs
```

Replace the local state hook with the optional adapter:

```tsx
import { useUrlFilters } from "@mendylanda/ui/filters/nuqs";

const filters = useUrlFilters(definitions, {
  scope: `issues:${organizationId}:${userId}`,
  remember: "session",
});
```

Provide the nuqs adapter once at the application root. For Next.js App Router:

```tsx
import type { ReactNode } from "react";
import { NuqsAdapter } from "nuqs/adapters/next/app";
import "@mendylanda/ui/styles.css";

export default function Layout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>
        <NuqsAdapter>{children}</NuqsAdapter>
      </body>
    </html>
  );
}
```

Statically rendered Next.js pages using URL hooks need a Suspense boundary around the filter component. For Vite, use `nuqs/adapters/react`. Other routers can use the [nuqs adapters](https://nuqs.dev/docs/adapters).

The base package does not import nuqs or Next.js. Existing query-state hooks can instead connect through `bindFilters<YourState>()` and `useControlledFilters`. See [dynamic and custom filters](/docs/advanced).

## Behavior

Selections, dates, and number ranges apply immediately. Text and token drafts save with Enter. Predefined shortcuts apply on the first click and open their editor on the second. The menu stays open by default.

The filter list and editor share a panel on desktop. On mobile, the editor replaces the list and offers Back. Menu changes are instant, and chip entry animations respect reduced motion.

Hover previews a filter on desktop. While a text input has focus, click another filter to switch. Unapplied drafts and option searches survive switching filters or using mobile Back; closing the menu discards them.

Arrow keys move through the filter list. Enter or the arrow toward the editor enters it. The return arrow moves back to the list, while text inputs and calendars keep their own arrow-key behavior. Tab moves through the visible controls and then continues after the trigger in the page. Shift+Tab from the list returns to the trigger. Escape closes the desktop menu; on mobile it first returns to the list.

## Customization

Use theme variables, named `classNames`, typed `renderOption`, `renderSummary`, and `renderEditor` callbacks, or compose your own layout. `MendyUIProvider` can replace controls and set a portal container. See the [customization guide](/docs/customization).

## Updating

```sh
npm update @mendylanda/ui
```

Review the [changelog](https://github.com/MendyLanda/mendy-ui/blob/main/CHANGELOG.md), test, and deploy the consuming project. Its lockfile controls the installed version. Updating the dependency brings in the shared implementation without copying or merging component files.

For a project previously using the registry, replace imports with the package exports, import the stylesheet, and remove the copied Mendy UI implementation after migrating its callers. Keep your definitions, queries, and custom editors. Move local visual changes to the documented customization points.
