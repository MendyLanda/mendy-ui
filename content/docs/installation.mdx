## Install

Use React 19, TypeScript, Tailwind CSS 4, and Radix-based shadcn components. Run this in your application:

<InstallCommand />

This installs the typed definitions, filter bar, local and controlled state hooks, dynamic option support, and nuqs persistence, together with the underlying filter components. Imports follow your `components.json` aliases.

## Set up the URL adapter

For Next.js App Router, wrap your app in `NuqsAdapter` from `nuqs/adapters/next/app`. For Vite, use `nuqs/adapters/react`. Follow the [nuqs adapter instructions](https://nuqs.dev/docs/adapters) for other supported routers. Statically rendered Next.js pages using URL hooks need a Suspense boundary around the filter component.

```tsx
import type { ReactNode } from "react";
import { NuqsAdapter } from "nuqs/adapters/next/app";

export default function Layout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>
        <NuqsAdapter>{children}</NuqsAdapter>
      </body>
    </html>
  );
}
```

## Define your filters

```tsx
"use client";

import { defineFilters, filter } from "@/components/ui/filter-definition";
import { FilterBar } from "@/components/ui/filter-bar";
import { useUrlFilters } from "@/components/ui/use-url-filters";

const definitions = defineFilters({
  status: filter.select({
    label: "Status",
    options: [
      { value: "open", label: "Open" },
      { value: "closed", label: "Closed" },
    ],
    suggestion: { value: "open" },
  }),
  owner: filter.multiSelect({
    label: "Owner",
    options: [{ value: "mendy", label: "Mendy" }],
    searchable: true,
  }),
});

export function IssueFilters() {
  const filters = useUrlFilters(definitions, {
    scope: "issues",
    remember: "session",
  });

  // filters.values.status is "open" | "closed" | null.
  // Use filters.values and filters.search in your data query.
  return <FilterBar filters={filters} />;
}
```

Use a scope that includes the organization or user when remembering scoped data, for example `issues:${organizationId}:${userId}`. Session restoration only runs when the URL has no managed filter parameters. Explicit URL values take precedence.

Opening an editor does not change the URL. Choosing a value applies it. Dates and number ranges apply immediately. Text and token drafts save with Enter. Suggested filters have dashed borders; clicking a suggestion with a preset applies it and keeps its editor open. Other suggestions stay visible.

The filter menu stays open after applying so you can add several filters. Use `<FilterBar closeMenuOnApply />` to close it after each successful change.

## Local or existing state

Use `useFilters(definitions)` when the values should stay local. It returns the same filter-bar controller, including `values`, `search`, and the typed `set` method.

Use `bindFilters<YourState>()` and `useControlledFilters` to connect existing query or persistence hooks. See [dynamic and custom filters](/docs/advanced) and the [system reference](/docs/system).

## Optional namespace

```json
{
  "registries": {
    "@mendy-ui": "https://ui.mendylanda.com/r/{name}.json"
  }
}
```

Then install with `npx shadcn@latest add @mendy-ui/filter-system`.

## Updating an installation

Installed source belongs to your app. Commit local changes before reinstalling, then review the diff. Keep your application definitions in a separate file so future component changes are easier to merge. Review the [changelog](https://github.com/MendyLanda/mendy-ui/blob/main/CHANGELOG.md) for behavior and migration notes.
