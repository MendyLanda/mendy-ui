## Remote options and paste

<AdvancedFiltersDemo />

This example searches a simulated asynchronous data source, loads more options, and resolves selected IDs separately. Open a link with `?owner=["sam"]` to see label resolution without opening the menu. The example remembers filters in this browser session when there are no explicit filters in the URL.

Paste `ISSUE-123` or `alex@example.com` into search, or type them and press Enter. They become editable chips automatically. These fields use `menu: false` so the menu stays focused on choices such as owner and date. `#123` deliberately matches two fields so you can choose its destination. Unrecognized text stays in search.

Large selections remain applied and are saved in this browser session. The notice explains when the URL cannot reproduce the full selection in another browser.

## Existing state and custom editors

<ProjectFiltersDemo />

Both sets use the same definitions with independent local state. Created date uses a calendar for a single day or a range while preserving separate start and end fields. Status and Tags group related controls with section dividers, compact Yes/No toggles, and colored tag options. The custom member editor summarizes whole teams when all their members are selected. Changing Workspace updates available projects while retaining existing selections.

Pass an existing persistence callback to `useControlledFilters`, or keep a saved view draft in local state. Neither has to change the application's backend query shape.
