## Start with rows and columns

After [installation](/docs/installation), this is a complete table:

```tsx
"use client";
import { DataTable, defineColumns, format } from "@mendylanda/ui/table";

type Project = { id: string; name: string; budget: number };
const rows: Project[] = [
  { id: "website", name: "Website", budget: 2400 },
  { id: "mobile", name: "Mobile app", budget: 5600 },
];
const columns = defineColumns<Project>((column) => [
  column.accessor("name", { label: "Project", pin: "start" }),
  column.accessor("budget", { label: "Budget", format: format.currency("USD", "en-US") }),
]);

export function ProjectsTable() {
  return <DataTable rows={rows} columns={columns} getRowId={(row) => row.id} label="Projects" />;
}
```

Use an ID that identifies the record across sorting, filtering, and page loads. An array index is not a stable record identity.

## What comes by default

| Behavior        | Default                                                                              |
| --------------- | ------------------------------------------------------------------------------------ |
| Rendering       | Virtual rows and columns, sticky header, 44px rows.                                  |
| Columns         | Resizing, settings, visibility, reordering, pinning, and spare-width sharing.        |
| Data processing | Client sorting and filtering; pagination off.                                        |
| Cell selection  | Drag and keyboard selection, with spreadsheet-style copying.                         |
| Row selection   | Opt in with `enableRowSelection`; checkboxes appear inside the first visible column. |
| Height          | Fit content, capped at 65dvh. Use `layout="fill"` for a full-page table.             |
| Appearance      | Your application's semantic colors, font, and radius.                                |

Filters, pagination controls, row actions, and saved preferences are configured when needed. They are not required to render a table.

## Connect your application

Use `useDataTable` when the query or other controls need access to state. Pass the resulting instance to `<DataTable table={table} />`. For a custom arrangement, compose `TableView`, `TableFilters`, `TableColumnSettings`, and other controls around that instance.

- [Columns and rendering](/docs/table/columns): typed accessors, computed values, custom cells, and formatters.
- [Layout and sizing](/docs/table/layout): embedded tables, full-page tables, growing columns, and expanded rows.
- [Data and queries](/docs/table/data): loading, errors, filters, server sorting, and incremental loading.
- [Selection and clipboard](/docs/table/selection): cells, rows, all matching results, and export.
- [Preferences and saved views](/docs/table/preferences): persistence and application-owned views.
- [Performance](/docs/table/performance): what virtualization covers and where application work remains.

The [API reference](/docs/table/api) lists the props and exported functions.
